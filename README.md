## קטלוג חלקי חילוף — VRF (גרסת Supabase)

אותו אתר, אבל הנתונים שלו נשמרים ב-**Supabase** ולא בדפדפן, כך שכל מי שנכנס רואה את אותו קטלוג מעודכן.
האתר עצמו (הקבצים) יושב ב-**GitHub Pages**. הכניסה בסיסמה בלבד, בלי Supabase Authentication.

### מבנה הקבצים
```
📁 catalog/
  index.html              ← נקודת כניסה (העיצוב וה-CDN של React / Babel / Excel)
  README.md
  .nojekyll               ← קובץ ריק שמבטיח ש-GitHub Pages מגיש את הקבצים כמו שהם
  📁 js/
    config.js             ← כתובת Supabase והמפתח הציבורי (חדש)
    supabasedb.js         ← מחליף את localdb.js: מדבר עם Supabase ומחקה את ממשק Firestore (חדש)
    constants.js          ← קבועים (הוסרו סיסמאות ברירת המחדל)
    storage.js            ← טעינה ושמירה (טעינה מהירה בקבוצות, תמונות כמסמכים נפרדים)
    helpers.js            ← עזרים; נוספו SbImg (תמונות מהענן) ו-escHtml (הדפסה בטוחה)
    components.js         ← מסך כניסה (הסיסמה נבדקת בשרת), דף הבית, סל וכו'
    modals.js             ← חלונות; ניהול משתמשים עבר לשרת
    ModelView.js          ← עמוד דגם
    compare.js            ← השוואת דגמים
    makat_review.js       ← בדיקת מק"טים
    App.js                ← האפליקציה: כניסה, טעינה אחרי כניסה, שמירה אוטומטית
  📁 sql/
    1-schema.sql          ← מסד הנתונים וההרשאות (מריצים פעם אחת ב-Supabase)
    2-first-users.sql     ← המשתמשים הראשונים (מריצים פעם אחת)
  📁 .github/workflows/
    keepalive.yml         ← בקשה קטנה כל 3 ימים שמונעת מהפרויקט החינמי להיעצר
```
הקובץ `localdb.js` וקובץ `catalog-data.json` כבר לא בשימוש.

### הקמה (חד-פעמית, כ-10 דקות)

**1. מסד הנתונים.** ב-Supabase: **SQL Editor ← New query**. פתח את `sql/1-schema.sql`, **העתק את כל התוכן** (לא את שם הקובץ), הדבק ולחץ **Run**. אפשר להריץ שוב בלי נזק.
הוא משתמש בסכמה פרטית בשם `vrf` ובפונקציות `vrf_*`, ולכן אפשר להריץ אותו באותו פרויקט Supabase של אתרים אחרים (למשל אתר המפוצלים) בלי להתנגש בהם.

**2. המשתמשים הראשונים.** פתח את `sql/2-first-users.sql`, החלף את הסיסמאות שבו לסיסמאות שלך (מנהל: לפחות 10 תווים, עורך: 6, צופה: 4), הדבק ב-SQL Editor ולחץ **Run**. אחר כך מחק את הסיסמאות מהחלון. את שאר המשתמשים מוסיפים מתוך האתר (ראה למטה).

**3. הגדרות האתר.** ב-`js/config.js` כבר מוגדרים הכתובת והמפתח הציבורי (publishable) של הפרויקט שלך. אם אתה משתמש בפרויקט Supabase אחר, החלף אותם. **לעולם אל תכניס לשם מפתח secret או service_role.**

**4. GitHub Pages.** העלה את כל התיקייה למאגר (כולל `.github` ו-`.nojekyll`), ואז **Settings ← Pages ← Branch: main / (root)**. האתר זמין אחרי דקה ב-`https://<שם-משתמש>.github.io/<שם-מאגר>/`.
אחרי כל החלפת קבצים רענן עם **Ctrl+F5**.

### מעבר מהאתר הקיים (העברת הנתונים)
1. באתר הקיים, כמנהל: תפריט ⋮ ← **ייצוא גיבוי (JSON)**.
2. באתר החדש, כמנהל: תפריט ⋮ ← **ייבוא גיבוי (JSON)** ובחר את הקובץ. האתר ישמור הכול ב-Supabase לבד (כולל התמונות). בקטלוג גדול זה יכול לקחת כמה דקות: חכה עד שסימן הדיסקט בראש העמוד נעלם.
3. **מחק את קובץ הגיבוי אחרי הייבוא.** בגיבויים של האתר הישן יש סיסמאות בטקסט גלוי. האתר החדש מתעלם מהן ולא שומר אותן בשום מקום; הסיסמאות החדשות הן אלה שהגדרת ב-`2-first-users.sql`.

### ניהול משתמשים וסיסמאות
תפריט ⋮ ← **ניהול משתמשים** (מנהל בלבד): הוספה, שינוי שם ותפקיד, החלפת סיסמה ומחיקה.
* הכניסה היא לפי סיסמה בלבד, ולכן לכל משתמש חייבת להיות סיסמה שונה. השם נקבע לפי הסיסמה ומופיע בלוג.
* כל שינוי דורש להקליד את סיסמת המנהל שלך לאישור (כך שמי שמצא מחשב פתוח לא יכול להחליף סיסמאות).
* הסיסמאות שמורות בשרת מגובבות ואי אפשר לראות אותן, רק להחליף.
* מי שהסיסמה או התפקיד שלו הוחלפו מנותק מיד.
* אי אפשר למחוק את עצמך, ואי אפשר להסיר את המנהל האחרון.

### תמונות ושרטוטים
תמונה שמועלית נשמרת כמסמך נפרד, ובדגם נשמרת רק הפניה אליה. כך הקטלוג נטען מהר, והתמונות נטענות רק כשפותחים דגם.
כשמסירים תמונה או מוחקים דגם, התמונה נשארת בענן (אפשרות הניקוי הוסרה מהתפריט).
גיבוי JSON כולל את התמונות בתוכו, כך שהקובץ שלם.

### אבטחה: מה מוגן ומה כדאי לדעת
* הטבלאות בסכמה פרטית שה-API של Supabase לא חושף. המפתח הציבורי לבדו לא נותן גישה לשום נתון, והכול עובר דרך פונקציות שבודקות אסימון והרשאה בשרת.
* הסיסמה נבדקת במסד הנתונים ולא בדפדפן. אחרי 8 ניסיונות שגויים נחסמת הכתובת ל-15 דקות.
* אסימון עורך ומנהל תקף 12 שעות ונשמר רק בלשונית הפתוחה. אסימון צופה תקף 30 יום ונשמר במכשיר.
* ערכים שנכנסים לחלונות PDF והדפסה עוברים escape, כדי שעורך לא יוכל להסתיר קוד בשם חלק.
* האתר ציבורי, ולכן סיסמת המנהל חייבת להיות ארוכה ולא צפויה. מי ששולט בסיסמת הצפייה יכול לקרוא את כל מה שאינו מוסתר.

### מגבלות ומה לעשות
* **שני עורכים בו-זמנית:** שמירה היא "האחרון מנצח" ברמת הדגם. כל עורך שומר רק את הדגמים שערך. כדי להימנע מהתנגשות, אל תערכו את אותו דגם באותו זמן. המשתמשים מקבלים עדכונים של אחרים בטעינה הבאה של האתר.
* **גיבוי:** במסלול החינמי של Supabase אין גיבויים אוטומטיים. הורד מדי פעם **ייצוא גיבוי (JSON)** כמנהל.
* **פרויקט חינמי** נעצר אחרי שבוע בלי פעילות. הקובץ `keepalive.yml` שולח בקשה כל 3 ימים. GitHub עלול להשבית משימות מתוזמנות במאגר שלא השתנה זמן רב, ולכן הציץ בלשונית Actions מדי פעם.
* **נפח:** התוכנית החינמית כוללת 500MB למסד הנתונים (Dashboard ← Reports ← Database).
* גרסאות שמורות (שחזור) נשמרות רק כשהקטלוג המלא קטן מ-3MB. בקטלוג גדול הן מדולגות, ולכן הגיבוי הידני חשוב.

## גיבוי ושחזור (מנהל)

תפריט ⋮ ← **גיבוי מלא (ZIP)**: מוריד קובץ אחד עם תיקיות לפי שנתון / קטגוריה / דגם. בכל דגם: התמונות כקבצים ו"רשימת-חלקים.csv" (נפתח באקסל), וגם `כל-החלקים.xlsx` ו-`backup.json`.

תפריט ⋮ ← **שחזור מגיבוי**: בוחרים את קובץ ה-ZIP (או קובץ JSON ישן), והקטלוג כולו מוחלף בתוכן הגיבוי. קובץ הקוד החדש: `js/backup.js`. סיסמאות ומשתמשים לא נכללים.
