# מרכז חלקי חילוף למזגנים מפוצלים

אתר סטטי (HTML + JavaScript, בלי שלב build) שנשמר ב-**GitHub** ומתפרסם ב-**GitHub Pages**.
כל הנתונים, המשתמשים והקבצים (סכמות פיצוץ ותמונות) נשמרים ב-**Supabase**, כך שכל הטכנאים רואים אותו מידע.

**מבנה המידע:** מותג ← דגם (עם שנתון אופציונלי) ← מעבה + מאיידים ← חלקי חילוף וסכמות.
מעבה אחד יכול לשרת כמה דגמים או שנתונים בלי להשתכפל.

## הקמה (חד-פעמית, כ-15 דקות)

### 1. מסד הנתונים
ב-Supabase: **SQL Editor ← New query**, הדבק את כל הקובץ `sql/schema.sql` ולחץ **Run**.
הסקריפט יוצר טבלאות, כללי הרשאה (RLS) ו-bucket פרטי לקבצים. בטוח להריץ שוב, והוא לא מוחק נתונים.

### 2. שני משתמשים
**Authentication ← Users ← Add user ← Create new user**, פעמיים. סמן **Auto Confirm User**.

| תפקיד | אימייל | סיסמה |
|---|---|---|
| מנהל | `admin@parts.example.com` | **סיסמה חזקה שתבחר (12 תווים ומעלה)** |
| צפייה | `viewer@parts.example.com` | הסיסמה שתמסור לטכנאים |

* בכניסה לאתר מקלידים **רק סיסמה**. האתר מנסה אותה מול שני החשבונות ומפעיל את התפקיד המתאים.
* הסיסמאות נשמרות רק ב-Supabase. הן לא נמצאות בקוד ולא ב-GitHub.
* האתר ציבורי ואפשר לנסות לנחש בו סיסמאות, ולכן סיסמת המנהל צריכה להיות חזקה. סיסמת הצפייה יכולה להיות פשוטה יותר.
* **כבה הרשמה עצמית:** בהגדרות Authentication כבה את "Allow new users to sign up". כללי ההרשאות ממילא חוסמים כל משתמש שאינו אחד משני החשבונות, אבל אין סיבה להשאיר את האפשרות פתוחה.

### 3. פרסום ב-GitHub
1. צור מאגר חדש (למשל `tadiran-split-parts`) והעלה אליו את **כל** תוכן התיקייה הזו (כולל `.github` ו-`.nojekyll`).
2. **Settings ← Pages ← Build and deployment**: Source = *Deploy from a branch*, Branch = `main`, תיקייה `/ (root)`.
3. אחרי דקה האתר זמין ב-`https://<שם-המשתמש>.github.io/<שם-המאגר>/`.

בחשבון GitHub חינמי, Pages דורש מאגר ציבורי. זה בסדר: בקוד אין שום סוד, רק כתובת הפרויקט והמפתח הציבורי (publishable).

### 4. שימוש ראשון
היכנס עם סיסמת המנהל ← **ניהול ← ייבוא מ-Excel** ← בחר תיקייה (שם התיקייה הופך לשנתון) ← בחר מותג ← אישור ושמירה.

## הגדרות (`js/config.js`)
כתובת הפרויקט, המפתח הציבורי, שתי כתובות המייל, שם ה-bucket וגדלי קבצים מקסימליים.
אם משנים את כתובות המייל, חייבים לשנות אותן גם בפונקציה `app_role()` ב-`sql/schema.sql` ולהריץ אותו שוב.

**אסור** להכניס ל-`config.js` מפתח `secret`/`service_role` או סיסמת מסד נתונים.

## איך האבטחה עובדת
* ההרשאות נאכפות **במסד הנתונים** (Row Level Security) ובאחסון הקבצים, לא רק בממשק. צופה יכול רק לקרוא. גם מי שפונה ישירות ל-API עם חשבון הצפייה לא יכול לשנות או למחוק.
* משתמש שאינו אחד משני החשבונות לא רואה כלום. גישה אנונימית חסומה לגמרי.
* אותו מק"ט תדיראן לא יכול להופיע פעמיים ביחידה אחת, ושם מותג לא יכול להופיע פעמיים: זה נאכף גם במסד.
* מחיקת מותג, דגם או יחידה מוחקת גם את הקבצים שלהם.

## ייבוא Excel
נתמכים XLS ו-XLSX. אפשר לבחור תיקייה שלמה (בחירת תיקייה נתמכת ב-Chrome וב-Edge במחשב). המערכת מזהה לבד:
* **גיליון יחידה**: כותרות `Part Description` ו-`TADIRAN P/N` (או "שם החלק" ו"מק״ט תדיראן"), ושורות `Product Model / Product Code / EV Chart` מעליהן.
* **מאייד או מעבה**: משם הגיליון (IDU/ODU/פנימית/חיצונית) או מסיומת הדגם (`/I`, `/O`).
* **סכמת פיצוץ**: התמונה שבגיליון נשלפת ונשמרת כסכמת היחידה (כולל תמונות EMF שמודבקות מ-Excel, שהן מומרות ל-PNG).
* **קטלוג מק"טים כללי**: גיליון עם עמודות "חומר" ו"תיאור".

לפני השמירה מוצגת תצוגה מקדימה שבה אפשר לתקן שנתון, שם דגם, סוג יחידה ומספר דגם. אין דריסה של נתונים קיימים: מק"ט כפול ביחידה ותמונה זהה מדולגים, ושורה בלי מק"ט תדיראן תקין (חסר, `none`, `#N/A`, מספר קצר) מדולגת אלא אם בוחרים לייבא אותה.

## גיבוי ומגבלות
* **במסלול החינמי של Supabase אין גיבויים אוטומטיים.** השתמש בכפתורי **ניהול ← גיבוי נתונים (JSON)** ו-**ייצוא הכל ל-Excel** מדי פעם. הגיבוי כולל נתונים אך לא את קובצי הסכמות והתמונות.
* פרויקט חינמי עלול להיעצר אחרי תקופה ארוכה בלי פעילות. הקובץ `.github/workflows/keepalive.yml` שולח בקשה קטנה כל 3 ימים כדי לצמצם את הסיכון. GitHub עלול להשבית משימות מתוזמנות במאגר שלא השתנה זמן רב, ולכן כדאי להציץ בלשונית Actions מדי פעם ולהפעיל ידנית אם צריך. אם הפרויקט נעצר, מפעילים אותו מחדש מהדשבורד של Supabase.
* נפח מסד הנתונים ואחסון הקבצים מוגבלים לפי תוכנית ה-Supabase שלך. עקוב אחריהם בדשבורד.
* האתר טוען את כל החלקים בכניסה, כדי שהחיפוש יהיה מיידי. זה מתאים לעשרות אלפי חלקים. אם המאגר יגדל הרבה מעבר לזה, יש לעבור לחיפוש בצד השרת.
* שני מנהלים שעורכים את אותה רשומה באותו זמן: האחרון שמירה מנצח. צופים מקבלים עדכון אוטומטי כשחוזרים ללשונית, ומנהל יכול ללחוץ על ⟳.

## פתרון תקלות
| הודעה | משמעות |
|---|---|
| סיסמה שגויה | הסיסמה אינה אחת משתי הסיסמאות שהוגדרו ב-Supabase |
| המשתמש קיים אבל לא מאושר | המשתמש נוצר בלי **Auto Confirm User** |
| מפתח ה-Supabase אינו תקין | יש לבדוק את `supabaseKey` ב-`js/config.js` |
| אין הרשאה לבצע את הפעולה | נכנסת עם חשבון הצפייה, או ש-`sql/schema.sql` לא הורץ / האימיילים לא תואמים |
| טעינת הנתונים נכשלה | לא הורץ `sql/schema.sql`, או שהפרויקט עצור |

## מבנה הקבצים
```
index.html            עמוד האתר
css/style.css         עיצוב (עברית, RTL, מובייל)
js/config.js          הגדרות
js/supabase.js        חיבור ל-Supabase (הזדהות, טבלאות, קבצים), בלי ספריות חיצוניות
js/store.js           שכבת נתונים: שולחת לענן רק את מה ששונה ומחזירה למצב הענן אם שמירה נכשלה
js/importer.js        זיהוי ייבוא Excel וחילוץ תמונות
js/sheetio.js         קריאה וכתיבה של XLS/XLSX
js/app.js             הממשק
sql/schema.sql        מסד נתונים והרשאות
.github/workflows/    משימת השארת הפרויקט ער
```
