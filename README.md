# מרכז חלקי חילוף למזגנים מפוצלים

אתר סטטי (HTML + JavaScript, בלי שלב build) שנשמר ב-**GitHub** ומתפרסם ב-**GitHub Pages**.
כל הנתונים והקבצים (סכמות פיצוץ ותמונות) נשמרים ב-**Supabase**, כך שכל הטכנאים רואים אותו מידע.
**אין Supabase Authentication ואין משתמשים**: נכנסים עם סיסמה בלבד.

**מבנה המידע:** מותג ← דגם (עם שנתון אופציונלי) ← מעבה + מאיידים ← חלקי חילוף וסכמות.
מעבה אחד יכול לשרת כמה דגמים או שנתונים בלי להשתכפל.

## הקמה (חד-פעמית, כ-10 דקות)

### 1. מסד הנתונים
ב-Supabase: **SQL Editor ← New query**, הדבק את כל הקובץ `sql/schema.sql` ולחץ **Run**.
בטוח להריץ שוב, והוא לא מוחק נתונים ולא משנה סיסמאות.

### 2. שתי הסיסמאות
פתח את `sql/set-passwords.sql`, החלף את שתי הסיסמאות שבו לסיסמאות שלך, הדבק ב-SQL Editor והרץ.
* **סיסמת מנהל** (לפחות 10 תווים): עריכה, הוספה, מחיקה, ייבוא.
* **סיסמת צפייה** (לפחות 4 תווים): את זו מוסרים לטכנאים.
* אחרי ההרצה מחק את הסיסמאות מחלון ה-SQL. אל תעלה אותן ל-GitHub.
* אפשר להריץ שוב בכל זמן כדי להחליף סיסמאות. כל המחוברים יתנתקו.

### 3. פרסום ב-GitHub
1. צור מאגר חדש (למשל `tadiran-split-parts`) והעלה אליו את **כל** תוכן התיקייה הזו (כולל `.github` ו-`.nojekyll`).
2. **Settings ← Pages ← Build and deployment**: Source = *Deploy from a branch*, Branch = `main`, תיקייה `/ (root)`.
3. אחרי דקה האתר זמין ב-`https://<שם-המשתמש>.github.io/<שם-המאגר>/`.

בחשבון GitHub חינמי, Pages דורש מאגר ציבורי. זה בסדר: בקוד אין שום סוד, רק כתובת הפרויקט והמפתח הציבורי (publishable), והוא לא נותן גישה לנתונים בלי סיסמה.

### 4. שימוש ראשון
היכנס עם סיסמת המנהל ← **ניהול ← ייבוא מ-Excel** ← בחר תיקייה (שם התיקייה הופך לשנתון) ← בחר מותג ← אישור ושמירה.

## איך האבטחה עובדת (ומה המגבלות)
האתר ציבורי, ולכן לא די ב"סיסמה בדפדפן": מי שפותח את קוד האתר היה יכול לעקוף אותה ולפנות ישירות למסד. כדי למנוע זאת:
* הטבלאות נמצאות בסכמה פרטית שה-API של Supabase לא חושף בכלל. **המפתח הציבורי לבדו לא נותן גישה לשום נתון.**
* הדרך היחידה לגשת לנתונים היא פונקציות `sp_*` במסד. הן דורשות אסימון שנוצר רק אחרי כניסה עם סיסמה נכונה, **והסיסמה נבדקת במסד ולא בדפדפן**.
* הסיסמאות נשמרות מגובבות (hash עם מלח) בטבלה שאי אפשר לקרוא מבחוץ. אסימון הכניסה נשמר בצד השרת רק כגיבוב.
* צופה יכול רק לקרוא. גם מי שפונה ישירות ל-API עם אסימון צפייה לא יכול לשנות, למחוק או להעלות קבצים.
* אסימון מנהל תקף 12 שעות ונשמר רק בלשונית הפתוחה. אסימון צופה תקף 30 יום ונשמר במכשיר.
* **ניחוש סיסמאות:** אחרי 8 ניסיונות שגויים נחסמת הכתובת ל-15 דקות, וגם הסיסמה הנכונה לא תתקבל בזמן החסימה. יש גם תקרה כללית נגד ניחוש מבוזר, שגורמת להשהיית כל הכניסות לכמה דקות אם יש מתקפה.
* **מגבלה:** חסימה לפי כתובת IP מסתמכת על כתובת ש-Supabase מעביר למסד. סיסמה חזקה היא ההגנה העיקרית, ולכן סיסמת המנהל חייבת להיות ארוכה ולא צפויה. למי ששולט בסיסמת הצפייה יש גישת קריאה מלאה, אז מסור אותה רק למי שצריך.
* קבצים שמועלים נבדקים בשרת: רק PDF, JPG, PNG ו-WebP, והתוכן חייב להתאים לסוג (לא ניתן להעלות קובץ אחר בשם של תמונה).

## קבצים ונפח
הסכמות והתמונות נשמרות **בתוך מסד הנתונים** (כדי שגם אותן אפשר יהיה להגן בסיסמה) ולא ב-Supabase Storage, ולכן הן נספרות במכסת נפח המסד של התוכנית שלך. סכמה שנשלפת מ-Excel שוקלת בערך 150 עד 200KB. מאה סכמות הן כ-20MB. עקוב אחרי הנפח ב-Dashboard ← Reports ← Database. קובץ בודד מוגבל ל-20MB.

## גיבוי ומגבלות
* **במסלול החינמי של Supabase אין גיבויים אוטומטיים.** השתמש בכפתורי **ניהול ← גיבוי נתונים (JSON)** ו-**ייצוא הכל ל-Excel** מדי פעם. הגיבוי כולל נתונים אך לא את קובצי הסכמות והתמונות.
* פרויקט חינמי עלול להיעצר אחרי תקופה ארוכה בלי פעילות. הקובץ `.github/workflows/keepalive.yml` שולח בקשה קטנה כל 3 ימים כדי לצמצם את הסיכון. GitHub עלול להשבית משימות מתוזמנות במאגר שלא השתנה זמן רב, ולכן כדאי להציץ בלשונית Actions מדי פעם. אם הפרויקט נעצר, מפעילים אותו מחדש מהדשבורד של Supabase.
* האתר טוען את כל החלקים בכניסה, כדי שהחיפוש יהיה מיידי. זה מתאים לעשרות אלפי חלקים.
* שני מנהלים שעורכים את אותה רשומה באותו זמן: האחרון שמירה מנצח. צופים מקבלים עדכון אוטומטי כשחוזרים ללשונית, ומנהל יכול ללחוץ על ⟳.

## ייבוא Excel
נתמכים XLS ו-XLSX. אפשר לבחור תיקייה שלמה (בחירת תיקייה נתמכת ב-Chrome וב-Edge במחשב). המערכת מזהה לבד:
* **גיליון יחידה**: כותרות `Part Description` ו-`TADIRAN P/N` (או "שם החלק" ו"מק״ט תדיראן"), ושורות `Product Model / Product Code / EV Chart` מעליהן.
* **מאייד או מעבה**: משם הגיליון (IDU/ODU/פנימית/חיצונית) או מסיומת הדגם (`/I`, `/O`).
* **סכמת פיצוץ**: התמונה שבגיליון נשלפת ונשמרת כסכמת היחידה (כולל תמונות EMF שמודבקות מ-Excel, שהן מומרות ל-PNG).
* **קטלוג מק"טים כללי**: גיליון עם עמודות "חומר" ו"תיאור".

לפני השמירה מוצגת תצוגה מקדימה שבה אפשר לתקן שנתון, שם דגם, סוג יחידה ומספר דגם. אין דריסה של נתונים קיימים: מק"ט כפול ביחידה ותמונה זהה מדולגים, ושורה בלי מק"ט תדיראן תקין (חסר, `none`, `#N/A`, מספר קצר) מדולגת אלא אם בוחרים לייבא אותה.

## פתרון תקלות
| הודעה | משמעות |
|---|---|
| סיסמה שגויה | הסיסמה אינה אחת משתי הסיסמאות שהוגדרו |
| יותר מדי ניסיונות שגויים | נחסמת הכתובת לזמן קצר. המתן, או נקה את החסימה: `truncate sp.login_attempts;` ב-SQL Editor |
| עדיין לא הוגדרו סיסמאות | לא הורץ `sql/set-passwords.sql` |
| פונקציות מסד הנתונים לא נמצאו | לא הורץ `sql/schema.sql`, או שהפרויקט עצור |
| מפתח ה-Supabase אינו תקין | יש לבדוק את `supabaseKey` ב-`js/config.js` |
| ההתחברות פגה | הסשן הסתיים (או שהוחלפו הסיסמאות). יש להיכנס מחדש |

## מבנה הקבצים
```
index.html            עמוד האתר
css/style.css         עיצוב (עברית, RTL, מובייל)
js/config.js          הגדרות
js/supabase.js        חיבור למסד (כניסה בסיסמה, נתונים, קבצים), בלי ספריות חיצוניות
js/store.js           שכבת נתונים: שולחת לענן רק את מה ששונה ומחזירה למצב הענן אם שמירה נכשלה
js/importer.js        זיהוי ייבוא Excel וחילוץ תמונות
js/sheetio.js         קריאה וכתיבה של XLS/XLSX
js/app.js             הממשק
sql/schema.sql        מסד נתונים, הרשאות ופונקציות ה-API
sql/set-passwords.sql קביעת הסיסמאות
.github/workflows/    משימת השארת הפרויקט ער
```
